# GitHub Copilot Open OnDemand App

This Batch Connect app runs the interactive [GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli)
on a Slurm compute node and displays its full terminal interface in the browser. It uses
[ttyd](https://github.com/tsl0922/ttyd) as the web-terminal server; it does not require a
desktop environment, VNC, or a local installation on the user's computer.

## Prerequisites

- Open OnDemand with Batch Connect enabled and a Slurm cluster definition named `quests`.
- A Linux x86_64 compute-node environment with outbound HTTPS access to GitHub APIs,
  or an approved HTTP proxy.
- A GitHub Copilot plan. For organization-managed users, the organization must allow Copilot CLI.

## Install the shared software (no root required)

These steps install everything into a shared prefix that is readable by all users and mounted
on every compute node. Replace `/projects/<alloc>/shared/copilot_install` with the actual
shared path for your allocation.

### 1. Create the install prefix

```bash
PREFIX=/projects/<alloc>/shared/copilot_install
mkdir -p "${PREFIX}/bin"
```

### 2. Install the GitHub Copilot CLI

Use the official installer with a custom prefix so the binary lands in `${PREFIX}/bin`:

```bash
curl -fsSL https://gh.io/copilot-install | PREFIX="${PREFIX}" bash
```

Verify the binary is present and working:

```bash
"${PREFIX}/bin/copilot" --version
```

### 3. Install ttyd

Download the self-contained static Linux x86_64 binary from the
[ttyd releases page](https://github.com/tsl0922/ttyd/releases). Check that page for the
latest version number and replace `1.7.7` below if a newer release is available.

```bash
TTYD_VERSION="1.7.7"
curl -Lo "${PREFIX}/bin/ttyd" \
  "https://github.com/tsl0922/ttyd/releases/download/${TTYD_VERSION}/ttyd.x86_64"
chmod +x "${PREFIX}/bin/ttyd"
```

Verify on a compute node (not the login node) before proceeding:

```bash
srun --partition=<partition> --account=<account> \
     --ntasks=1 --mem=2G --time=00:05:00 --pty bash -c \
     "${PREFIX}/bin/ttyd --version"
```

If you see a `GLIBC_x.xx not found` error, the prebuilt binary is not compatible with the
node's glibc version. In that case, open a ticket with your HPC support team to request a
system-managed ttyd installation or build from source.

### 4. Update the app configuration

Open `form.yml.erb` and set the `copilot_binary` default value to the absolute path of the
`copilot` binary:

```yaml
  copilot_binary:
    value: "/projects/<alloc>/shared/copilot_install/bin/copilot"
```

Open `template/script.sh.erb` and set `TTYD_BINARY` to the absolute path of `ttyd`:

```bash
TTYD_BINARY="/projects/<alloc>/shared/copilot_install/bin/ttyd"
```

## Install the OnDemand app

Copy this directory into your OnDemand development app sandbox:

```bash
cp -r /path/to/quest_ood_copilot \
  ~/ondemand/dev/quest_ood_copilot
```

To promote it to a system app visible to all users, work with your OnDemand administrator
to copy the directory to `/var/www/ood/apps/sys/`.

If the target cluster is not named `quests`, change `cluster` in `form.yml.erb` to the
matching cluster key from `/etc/ood/config/clusters.d/`.

## User workflow

1. Open **Interactive Apps → Development → GitHub Copilot** in Open OnDemand and submit a job.
2. Set the partition, account, project directory, and resource request, then wait for the job
   to start.
3. Select **Connect to GitHub Copilot**. When prompted by the browser, enter your cluster
   username and the session password shown on the Open OnDemand session card.
4. Run `copilot login` if this is the first session for that Unix account, then use Copilot
   normally. Authentication data is stored in the user's home directory, not in the app.

## Security notes

- `ttyd` listens on the compute node and requires a per-session HTTP Basic Authentication
  credential generated by Open OnDemand. It is additionally accessed through Open OnDemand's
  authenticated node proxy.
- The app passes the selected project directory to Copilot with `-C`; Copilot can edit files
  only according to its own permission prompts and the user's Unix permissions.
- Do not configure a shared GitHub identity. Each user authenticates their own Copilot account.
